# MVP и порядок разработки

## Правило этапов

До закрытия Phase 0 **запрещены реальный deployment и работа с персональными данными**. Каждый этап начинается после принятия предыдущего; новые домены не добавляются «в обход» базовой безопасности.

## Phase 0 — безопасность и сохранность данных

**Scope:** убрать отслеживаемую рабочую БД из Git и подготовить безопасный seed без ПДн; подключить identity/session middleware и default-deny RBAC; реализовать заявки на регистрацию и ручное создание аккаунта с временным паролем; исправить auth flow, CSRF/Origin checks, cookie flags, rate limits, CSP-ready rendering; убрать XSS и внешний QR; версионировать embedded migrations с ledger; исправить критические инварианты ключей и shutdown; добавить базовые тесты. Контракт identity/access — в [IDENTITY_AND_ACCESS.md](IDENTITY_AND_ACCESS.md).

**Не входит:** новые сущности, визуальный ребрендинг, PostgreSQL, интеграции и ассистенты.

**Acceptance gates:**

- неавторизованный запрос к закрытому API получает 401/403; права проверены HTTP-тестами;
- саморегистрация не создаёт активный аккаунт; заявку рассматривают `admin` или `lab_head`, решение аудируется, а ручное одобрение, выдача временного пароля и обязательная смена пароля проверены HTTP-тестами;
- сессия не читается JavaScript, отзывается при logout/деактивации; CSRF и login rate limit протестированы;
- пользовательские значения не попадают в `innerHTML`; QR не отправляет URL третьей стороне;
- миграции повторяемы и записываются в ledger; чистая БД и upgrade проходят smoke test;
- рабочая БД, секреты и ПДн не в Git; восстановление backup проверено;
- Go build/test/vet проходят в согласованном окружении.

## MVP core — аккаунты, ключи, оборудование, аудит, backup

**Scope:** администратор создаёт/деактивирует аккаунты, а администратор или заведующий лабораторией рассматривает заявки на регистрацию; сотрудники входят в систему; матрица утверждённых прав; ключи с валидной машиной состояний и историей; оборудование с поиском, пагинацией, поверкой и ответственным; отдельная публичная карточка оборудования без внутреннего каталога; append-only audit; резервное копирование и процедура восстановления; новый app shell и базовые компоненты дизайн-системы. `guest` и `student` после входа пока видят только свой профиль и публичные карточки.

**Не входит:** мебель, химикаты, посуда, статьи, публичный каталог оборудования, интеграции.

**Acceptance gates:**

- все use cases MVP имеют авторизованного actor и audit event;
- нельзя получить держателя после возврата, создать недопустимый переход или обойти права прямым API;
- списки стабильны при фильтрации/пагинации, на mobile читаемы, а состояния loading/empty/error доступны;
- backup и restore выполнены на тестовом наборе; владелец принял роль/права и операционный сценарий.

## Next — мебель, химикаты, лабораторная посуда

**Scope:** отдельные доменные модули, поля, состояния, разрешения, аудит и экраны для каждого типа. Общие platform primitives переиспользуются только после подтверждения одинаковой семантики.

**Не входит:** слияние всех предметов в универсальную таблицу, закупочные/складские процессы, если они отдельно не согласованы.

**Acceptance gates:** для каждого модуля утверждены словарь полей, жизненный цикл, ответственный, правила списания/выдачи (если нужны), миграции, тесты и UX-сценарии.

## Next — статьи и статистика

**Scope:** реестр статей, статусы как конечный набор переходов, фильтры/таблица, статистика из подтверждённых данных и периодов.

**Не входит:** библиографические интеграции, автоматические метрики, внешняя публикация статистики без отдельного решения.

**Acceptance gates:** источник каждого показателя и формула определены; статусы нельзя менять вне state machine; доступ к данным и выгрузкам проверен.

## Future — справочник и ассистенты

**Scope:** после утверждения владельца контента, сценариев и политики доступа — справочник; затем ассистенты с ограниченными источниками, явным согласием на доступ к данным, журналом запросов/действий и безопасной деградацией.

**Не входит:** подключение модели к ПДн или операциям учёта по умолчанию.

**Acceptance gates:** утверждены источники, доступы, retention, human-in-the-loop для действий и критерии качества; проведена threat model review.
